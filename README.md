# 加油站 · 油枪与罐区巡检管理系统

加油站日常台账：**储罐与库存**、**卸油入罐**、**油枪台账**、**班次交接**、**罐区巡检**。

## 技术栈

Spring Boot 3.3（Java 17）+ MySQL 8.0 + Redis 7 + Vue 3 + Element Plus + Vite + nginx，全栈 `docker compose` 一键启动。

## 启动

```bash
./start.sh              # 等价于 docker compose up -d --build
```

| 入口 | 地址 |
| --- | --- |
| 前端页面 | http://127.0.0.1:8214/ |
| 后端接口 | http://127.0.0.1:8314/api/ |
| MySQL | 127.0.0.1:3514（库 `gas_station`） |
| Redis | 127.0.0.1:6514 |

## 停止

```bash
docker compose down       # 保留数据卷
docker compose down -v    # 连数据卷一起删，下次启动重新灌种子数据
```

## 业务模块

### 1. 储罐与库存（`tank`）

罐号 `T-xx` 全库唯一，记油品（`92# / 95# / 0# / -10#`）、罐容（升）、当前库存与安全库存线，
库存低于安全线时在列表里高亮。状态为 `在用 / 检修`。

写入时校验：罐容要大于 0；**当前库存要在 0 到罐容之间**；
**罐容不能改到比罐里现有的油少**；**罐里还挂着加油枪时不能转检修**；
**还有枪挂着的罐不能直接换油品**（不然枪出的油跟罐里的对不上）。

- 页面：储罐与库存（`/tanks`）
- 接口：`GET /api/tanks`、`POST /api/tanks`、`PUT /api/tanks/{id}`

### 2. 卸油入罐（`unloading`）

槽车到站先**开单**：记槽车牌、油品、计划升数，挂到一口现有储罐，单子停在 `待入罐`。
开单时服务端逐项核对：**油品必须和这口罐正在装的油一致**；**罐必须是在用，检修罐接不了卸**；
**计划升数 + 罐此刻库存不能超过罐容**。开单只写台账，**库存不动**。

真正「入罐」时再走一次服务端闸门（按安全员意见拍板）：

- 当天「**卸油口**」巡检还停在 `待处理`，不许入罐，库存更不许动；
- 点入罐时罐**已被改成检修**，本次失败；
- 罐**库存刚被别人加过**、本单再加会超罐容，本次失败。

失败时库存保持点之前的数，单子也不会变成 `已入罐`。同一口罐两张待入罐单同时入罐、
合起来超罐容时，入罐在数据库行锁里串行，**只许一单成功**。

- 只有入罐成功才把计划升数加进罐库存，单据置 `已入罐` 并记入罐时间；
- **已经入罐的单，升数和所挂的罐都不许再改**（整张单锁定）；待入罐单可改，改时重新核对全部规则。
- 页面：卸油入罐（`/unloadings`）
- 接口：`GET /api/unloadings`、`POST /api/unloadings`、`PUT /api/unloadings/{id}`、
  `POST /api/unloadings/{id}/enter`

### 3. 油枪台账（`fuel_gun`）

枪号 `G-xx` 全库唯一，记它挂在哪台加油机上、出什么油品、连哪个储罐，状态为 `可用 / 停用 / 维修`。

写入时校验：**枪的油品必须和所连储罐装的油一致**；**检修中的储罐不能挂枪**；
状态只认这三个值；**还挂着当班班的枪不许改成维修或停用**——机修要进场，
得先等这个班交掉，不然当班本子还按老读数往外交，这班油量就对不上是哪把枪跑的。

- 页面：油枪台账（`/guns`）
- 接口：`GET /api/guns`、`POST /api/guns`、`PUT /api/guns/{id}`

### 4. 班次交接（`shift_record`）

一个班 = 某天白班或夜班，**开班时选定一把当前可用的枪挂上去**，接班读数、交班读数
都是这把枪的读数，本班加油量与收款也记在这个班上。状态 `当班中 → 已交接`。

写入时校验：**同一天同一个班次只开一次**（数据库唯一键兜底并发撞班）；
**维修/停用的枪开不了班**，**一把枪同时只挂一个当班中的班**；
交班读数**不能小于**接班读数；**本班加油量由服务端算**（交班读数 − 接班读数），不用手填。

财务拍板的枪班联动：

- **当班中还挂着的枪，不许改成维修或停用**（改枪页会拦，报错写明先交班）；
- **点交班的那一刻枪已被改成维修/停用，这次交班必须失败**，班还停在 `当班中`，
  不会变成 `已交接`，等枪恢复可用再交；开班、交班、改枪状态都捏着这把枪的数据库行锁
  串行，同一把枪一边点维修、一边点交班，不会两头都落库；
- **已经交接的班，所挂的枪和两头读数都锁死**，整班不能再改；
  下一班接班读数对的就是上一班在同一把枪上交出去的读数。

- 页面：班次交接（`/shifts`）
- 接口：`GET /api/shifts`、`POST /api/shifts`、`PUT /api/shifts/{id}`、
  `POST /api/shifts/{id}/handover?endReading=&amount=`

### 5. 罐区巡检（`inspection`）

每天按点位巡检（例如 `T-01罐区`、`卸油口`），记正常还是异常、巡检人和问题描述。

写入时校验：**同一个点位同一天只能登记一条**；**报了异常就必须写清问题是什么**。
正常记录状态为 `已记录`；异常记录进 `待处理`，处理完标 `已处理`。

- 页面：罐区巡检（`/inspections`）
- 接口：`GET /api/inspections`、`POST /api/inspections`、`POST /api/inspections/{id}/resolve`

```
├── config/       CORS 配置

├── dto/          BizException + 统一错误响应
├── entity/       5 张业务表

backend/src/main/resources/schema.sql   建表 + 种子数据（挂进 MySQL initdb）
frontend/src/views/                     5 个业务页面
```
